# agnos

Rendered by `agnos build` (agnos v0.18.0) from that binary's own commands: never
edit it, the next build rewrites it. `agnos remove-skills` takes it away.

agnos is generated. Every `generated.<name>.go`, `docs/`, `README.md` and the wiring
between them are rendered from declarations: every change goes through a `agnos` command,
never an edit of what it renders.

## The loop

```bash
agnos <command> ...   # declares the change, then runs build for you
agnos build           # verify + regenerate + go mod tidy + compile; a second run changes nothing
agnos verify          # the schema check alone, writes nothing
```

Every command takes `--path <dir>` (default `.`) and `-q`. Run `build` after every hand edit; a
failed `verify` names the file and what to do.

## Never by hand

- A Go file named `generated.<name>.go`: it opens with `// Code generated by agnos. DO NOT EDIT.`
- A declaration — each has its editors:

| Declaration | Written by |
|---|---|
| `AgnosConfig/extensions.yaml` | `enable-extension` / `disable-extension`, every `<x>-init` / `<x>-purge` |
| `sandbox/internal/commands/**/command.yaml` | `add-command`, `add-flag`, `add-arg`, `set-command`, their `set-` / `remove-` pairs |
| `adapters/bindings/<name>/binding.yaml` | `add-dep` / `remove-dep`, `add-binding` / `remove-binding`, `set-adapter` |
| `examples/<side>/<name>/result.yaml` | `update-example <name>`, `run-examples --update` |

## What you write

A command's `handler.go`, beside its `command.yaml`:

```go
func Handle(sandbox *api.Sandbox, props *commandprops.CommandProps, input *Input, response *api.CommandResponse) error
```

`input` holds every arg and flag of `command.yaml`, already typed and checked. `response.Printf`
answers (exit 0), `response.Logf` is progress, and
`return sandbox.Deps.OpinionatedAgnosCli.Fail(api.ExitFailure, "", err.Error())` refuses (exit 1).

`sandbox/` imports only `sandbox/` packages, the stdlib included: the outside world is
`sandbox.Deps.<Contract>`, and OS-bound or third-party code lives in `adapters/impls/`. Reusable logic goes in
`sandbox/internal/<pkg>/`, every function taking `sandbox *api.Sandbox` first.

## Extensions

What `build` renders is `AgnosConfig/extensions.yaml`. A key that is off is turned on by its
`<x>-init` (`cli-init`, `server-init`, ...) or by `enable-extension <key>`.

| Key | On | Generates |
|---|---|---|
| `sandbox` | yes | the sandbox core: sandbox/generated.new.go, api/generated.sandbox.go, internal/config/generated.new.go |
| `deps` | yes | the dependency layer: sandbox/deps/, adapters/, bindings |
| `cli` | yes | the cli layer: cmd/main, help, version and the OpinionatedAgnosCli lib |
| `server` | no | the http layer: server/, routes/ and the OpinionatedAgnosServer lib |
| `front` | no | the front layer: the route serving assets/front/ and the OpinionatedAgnosFront lib |
| `database` | no | the database layer: the declared databases, --database and the OpinionatedAgnosDatabase lib |
| `example` | yes | the examples/ suite and run-examples |
| `backoffice` | no | the admin backoffice: login, users, API tokens, backups and the /api/admin JSON api |
| `doc` | yes | the docs/ tree and its Index.md files |
| `readme` | yes | README.md, built from themes.yaml and the doc index |
| `skills` | yes | the agent skills: .agents/skills/<generator>/ and .claude/skills/<generator>/, built from the generator's own commands |
