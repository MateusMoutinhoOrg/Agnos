# CLI Commands

## Description
Every command, flag, argument, output channel and exit code of the `agnos` command-line interface. The interface is `api.Sandbox.Cli.CliMain`, generated by `agnos build` from the `entries.yaml` of every command under `sandbox/internal/commands/`; the binary in [cmd/main](/cmd/main/) only wires an adapter into it and exits with what it returns. To install it, follow [InstallCli.md](/docs/Tutorials/InstallCli.md); to walk through a first project, follow [ScaffoldProject.md](/docs/Tutorials/ScaffoldProject.md). `agnos help <command>` prints the same information for one command.

```bash
agnos <command> [flags] [args]
```

---

## Common Flags

Every command that operates on a project carries these two flags. `--path` is the **only** way to name the project — a stray positional (`agnos build .`) is a usage error.

| Flag | Type | Description |
|------|------|-------------|
| `--path <dir>` | string, default `.` | The directory holding the project. An absolute boundary: every read, write and listing is scoped to it, and no generation ever escapes it. |
| `--quiet`, `-q` | boolean | Turns off the progress channel (standard error) for the run. Results and errors are still written. |

Flags may appear anywhere on the command line: the generated dispatch reads every declared flag first, then drains the positional arguments in order.

## Core Commands

| Command | Description |
|---------|-------------|
| `start --project-name <name> [--module <path>] [--force]` | Scaffolds a project into `--path`: writes `AgnosConfig/` (`project.yaml`, `themes.yaml`, `ignore.yaml`, `paths.yaml`), writes `go.mod` from `--module` (required when the directory has none; `--force`/`-f` overwrites an existing one), then runs `build`. `--project-name`/`-p` names the project and, lowercased, its binary. |
| `build [--runtime go\|none] [--unsafe]` | Runs `verify` (unless `--unsafe`), re-renders every generated file — see [GeneratedFiles.md](/docs/References/GeneratedFiles.md) — persists, then hands the project to the runtime: `go` (default) runs `go mod tidy` and `go build` over `./cmd/...`, `./sandbox/...`, `./adapters/...`; `none` renders only. |
| `verify [--runtime go\|none]` | Checks the tree against the harness schema and writes nothing; lists every violation at once and exits `1` on any. Then hands the project to the runtime like `build`. What is checked is in [BuildPipeline.md](/docs/References/BuildPipeline.md#the-verify-gate). |
| `compile --target <name>… [--path <dir>]` | Runs `build` (with the `go` runtime), creates `release/`, then cross-compiles `./cmd/main` once per `--target` into `release/<name>` with `CGO_ENABLED=0`. `--target`/`-t` repeats; `--target all` builds every one. Accepted names: `linux86` `linuxarm64` `linuxi32` `mac86` `macarm64` `windows86` `windowsi32` → `linux/amd64` `linux/arm64` `linux/386` `darwin/amd64` `darwin/arm64` `windows/amd64` `windows/386`, written to `linux86.out` `linuxarm64.out` `linuxi32.out` `mac86.bin` `macarm64.bin` `windows86.exe` `windowsi32.exe`. An unknown or empty target is a usage error (exit `2`). |

## Dependency System

| Command | Description |
|---------|-------------|
| `deps-init` | Creates `sandbox/deps/` and `adapters/`, then runs `build`, which renders `sandbox/deps/deps.go` and `adapters/availables/standard/new.go` and switches `sandbox/new.go` to take a `*deps.Deps`. Run once before `dep-install`. |
| `deps-purge` | Removes `sandbox/deps/` and `adapters/` whole, then runs `build` with the `none` runtime. |

---

## Dependencies

| Command | Description |
|---------|-------------|
| `dep-list` | Prints, to standard output, one line per dep under `assets/deplist/` that `dep-install` can render. The listing is in [DepList.md](/docs/References/DepList.md). |
| `dep-install <dep>` | Renders `assets/deplist/<dep>/**` into the project at the paths the files hold inside the dep, adds the dep's pinned `require` to `go.mod` when [depsversion.yaml](/assets/depsversion.yaml) lists it, persists, then runs `build`. |
| `dep-remove <dep>` | Deletes the files that dep installed plus any directory the removal emptied, strips its `require`, persists, then runs `build` with the `none` runtime. |

## Cli System

| Command | Description |
|---------|-------------|
| `cli-init` | Installs the `std` and `argvdeps` deps, renders the `cli` asset group (`cmd/main/main.go`, `sandbox/api/cli.go`, `sandbox/binds/cli.go`, `sandbox/internal/cli/climain.go`, the `help` and `version` commands), then runs `build`. |
| `cli-purge` | Removes every file of the `cli` group plus `sandbox/internal/cli/` and `sandbox/internal/commands/` **whole**, then runs `build` with the `none` runtime. The `std` and `argvdeps` deps are left in place. |
| `add-command <name> --help <text> --category <cat>` | Writes `sandbox/internal/commands/<name>/entries.yaml` (identifiers, category, help) and a stub `handler.go`, then runs `build`. `<name>` is normalized to `[a-z][a-z0-9-]*` and the normalization logged; `help` is refused. |
| `remove-command <name>` | Deletes `sandbox/internal/commands/<name>/` entirely, then runs `build` with the `none` runtime. `help` is refused. |
| `set-command <name> [--help <t>] [--category <c>] [--long-description <t>] [--hidden\|--visible] [--identifier <v>]… [--example <e>]…` | Rewrites the command-level keys of `entries.yaml`; keys not passed are untouched, `--identifier`/`-i` and `--example`/`-e` append and deduplicate. Then runs `build`. |
| `add-flag <name> --command <cmd> [--identifier <id>]… [--type string\|boolean\|int\|float] [--description <t>] [--example <e>]… [--default <v>] [--required] [--array] [--min <n>] [--max <n>] [--position <i>]` | Appends a flag to `<cmd>`'s `entries.yaml` and runs `build`. Identifiers default to `--<name>`; `--type` defaults to `string`; `--position` defaults to `-1` (append). A name or identifier `<cmd>` already uses is refused. |
| `remove-flag <name-or-identifier> --command <cmd>` | Drops a flag, matched by its name or by one of its identifiers, then runs `build` with the `none` runtime. |
| `add-arg <name> --command <cmd> [--type …] [--description <t>] [--example <e>]… [--default <v>] [--required] [--array] [--min <n>] [--max <n>] [--position <i>]` | Inserts a positional argument at `--position` (else last) and runs `build`. An `--array` argument must stay last. |
| `remove-arg <name> --command <cmd>` | Drops a positional argument, shifting later ones up, then runs `build` with the `none` runtime. |

`--command`/`-c` accepts the command's identifier or its package name. `--required`/`-r` is refused on a boolean and on a field with `--default`. `--min` / `--max` apply to `int` and `float` only. Every key of a field, and what the dispatch does with it, is in [EntriesYaml.md](/docs/References/EntriesYaml.md).

## Info

| Command | Description |
|---------|-------------|
| `help [command]`, `--help` | Without an argument, lists every visible command grouped by category; with one, prints that command's long description, usage, arguments, flags and examples. An empty command line prints the general help and exits `2`. |
| `version`, `--version` | Prints `Version:<version>` to standard output, from the `Version` constant `build` regenerates out of `AgnosConfig/project.yaml`. |

---

## Output Channels

Three channels, one meaning each, chosen by the CLI layer so no handler has to:

| Channel | Stream | Carries | Silenced by `--quiet` |
|---------|--------|---------|-----------------------|
| `deps.Std.Printf` | stdout | The command's **result**: the `dep-list` listing, the version string, a help screen. `agnos dep-list 2>/dev/null` is a clean machine-readable list. | No |
| `deps.Std.Log` | stderr | **Progress** notices: `build started with path .`, `runtime go: go mod tidy`. | Yes |
| `deps.Std.Error` | stderr | Usage errors and failures. | No |

---

## Exit Codes

| Code | Constant | Meaning |
|------|----------|---------|
| `0` | `api.ExitOk` | The command ran to completion. |
| `1` | `api.ExitFailure` | A well-formed command could not be carried out: a `verify` violation, a compile error from the runtime, an unknown dep, a command that already exists. |
| `2` | `api.ExitUsage` | The command line itself was wrong — an unknown command, an unknown flag (`--pathh`), a leftover positional, a missing required field, an unparsable or out-of-range number, an unknown `--runtime`. |

The dispatch rejects unknown input rather than ignoring it: after the declared flags are read, any still-unread argument starting with `-` is an unknown flag; after the declared positionals are drained, anything still unread is an unexpected argument.
